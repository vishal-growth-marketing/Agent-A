# QUALITY GATES

### Version: 1.0
### Owner: Team Leader
### Status: LIVE — Every deliverable must pass these gates before moving forward.

---

# WHAT THIS FILE IS

Quality Gates define when work is allowed to move through the operating system.

Every Skill is responsible for producing quality work.

Every gate is responsible for verifying it.

No deliverable moves forward simply because it exists.

It moves forward because it has passed the appropriate quality checks.

---

# QUALITY PRINCIPLES

## Rule 1 — Verify Before You Advance

Every stage verifies the work it receives before passing it to the next stage.

Never assume upstream work is correct.

Trust is earned through verification.

---

## Rule 2 — Every Gate Has One Responsibility

Each gate exists for a specific purpose.

Reviewer verifies completeness.

Legal Review verifies accuracy and risk.

CMO verifies strategic quality.

Release Manager verifies publication readiness.

No gate replaces another.

---

## Rule 3 — Stop Early, Not Late

The earlier a problem is found,

the cheaper it is to fix.

If a gate finds an issue,

stop,

return the work,

fix it,

then continue.

Never pass known problems downstream.

---

## Rule 4 — A Passed Gate Is Evidence

Every gate should clearly communicate one outcome.

PASS

RETURN

BLOCK

No ambiguous approvals.

Every downstream role should immediately understand the current state.

---

## Rule 5 — Quality Before Speed

Fast work that fails review costs more than slower work done correctly.

Never bypass a gate simply to finish sooner.

---

# QUALITY GATES

## Gate 1 — Team Leader

Verifies:

- Correct understanding of the request
- Appropriate execution plan
- Correct Skills selected

---

## Gate 2 — Reviewer

Verifies:

- Constitution read
- Execution read
- Required upstream inputs present
- Handoff complete
- Self-check completed
- Deliverable is complete

---

## Gate 3 — Legal Review

Verifies:

- Claims supported
- Sources verified
- No legal or compliance risks
- No misleading statements

---

## Gate 4 — CMO

Verifies:

- Business strategy
- Positioning consistency
- Market alignment
- Recommendation quality

---

## Gate 5 — Release Manager

Verifies:

- Ready for publication
- Correct formatting
- Channel readiness
- Final quality check

---

# WHEN A GATE FAILS

A failed gate never continues downstream.

The work returns to the responsible Skill or Orchestrator.

Only the failed issues should be corrected.

Previously approved work should not be recreated.

---

# SELF-CHECK

Before approving any gate ask:

> Did I actually verify this?

or

> Did I assume someone else already had?

If verification did not happen,

the gate has not passed.
