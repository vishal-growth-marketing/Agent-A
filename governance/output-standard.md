# OUTPUT STANDARD

### Version: 1.0
### Owner: Team Leader
### Status: LIVE — Defines the final format presented to the user.

---

# WHAT THIS FILE IS

Output Standard defines the only format that reaches the user.

Every Skill, Orchestrator, Reviewer, Legal Review, CMO, and Release Manager may generate intermediate work internally.

The user should never see that internal workflow.

The user receives one clear, consolidated deliverable.

---

# OUTPUT PRINCIPLES

## Rule 1 — One Deliverable

Regardless of how many Skills execute,

the user receives one final output.

The system thinks as a team.

It communicates as one.

---

## Rule 2 — Show Conclusions, Not Internal Work

Intermediate reasoning,

handoff documents,

review notes,

approval history,

and internal discussions remain inside the operating system.

Only the final decision reaches the user.

---

## Rule 3 — Every Output Must Answer The Request

The final deliverable should solve the user's problem.

Never force the user to combine multiple documents to understand the answer.

Synthesis is the system's responsibility.

---

## Rule 4 — Clarity Before Completeness

Present information in the simplest structure possible.

Longer is not better.

Every section should help the user make a decision or take action.

---

## Rule 5 — Consistency Builds Trust

Every output should feel like it came from the same experienced team.

Structure, terminology, formatting, and tone remain consistent regardless of which Skills participated.

---

```
────────────────────────────────────────

────────────────────────────────────────

Next Step

[Action for the user]

────────────────────────────────────────
```

---

# WHAT NEVER REACHES THE USER

The following remain internal:

- Skill outputs
- Handoff documents
- Review notes
- Legal Review comments
- CMO discussions
- Penalty logs
- Self-check results
- Internal planning
- Chain of execution

These exist to improve quality,

not to increase the user's reading.

---

# SELF-CHECK

Before presenting the final output ask:

> If the user never knew multiple Skills collaborated,

would this still feel complete?

If not,

simplify.
