# HANDOFF RULES

### Version: 1.0
### Owner: Team Leader
### Status: LIVE — Governs how work moves between Skills and Orchestrators.

---

# WHAT THIS FILE IS

Handoff Rules define how work moves through the operating system.

A Skill's responsibility is not finished when it produces an output.

It is finished when the next Skill has everything required to continue without repeating work or making assumptions.

Every handoff should reduce uncertainty, not create it.

---

# HANDOFF PRINCIPLES

## Rule 1 — No Skill Starts Empty

No Skill begins from a bare instruction.

Every Skill receives:

- The approved plan from Team Leader
- The required upstream outputs
- Constitution
- Execution
- Its own Role File

If any required input is missing,

the Skill stops and notifies Team Leader.

It never fills gaps with assumptions.

---

## Rule 2 — Build Once. Reuse Everywhere.

A downstream Skill should never repeat work that has already been completed upstream.

Research is reused.

Positioning is reused.

Approved terminology is reused.

Every Skill builds on previous work instead of recreating it.

---

## Rule 3 — Pass Decisions, Not Documents

A handoff should provide the decisions the next Skill needs.

Not every paragraph that was written.

Every output should clearly identify:

- What was decided
- Why it matters
- What the next Skill should use

The next Skill should never search through an entire document looking for one important insight.

---

## Rule 4 — Reuse Requires Visibility

When reusing previous work,

identify what is being reused.

If information comes from an earlier session,

say so.

Never present reused information as newly verified.

---

## Rule 5 — Unknown Stays Unknown

If a required input is missing,

say it is missing.

Do not guess.

Do not invent.

Do not continue simply to keep work moving.

---

# STANDARD EXECUTION FLOW

```
Market Research
        ↓
ICP Research
        ↓
Competitor Analysis
        ↓
Product Positioning
        ↓
SEO / GEO / Content / Landing Page / LinkedIn
        ↓
Marketing Audit
```

Team Leader may reuse approved upstream work when appropriate.

When doing so,

the reused inputs must be explicitly identified.

---

# HANDOFF BLOCKS

Every Skill should include clearly labelled sections for downstream consumers.

Examples:

- FOR ICP RESEARCH
- FOR COMPETITOR ANALYSIS
- FOR PRODUCT POSITIONING
- FOR SEO STRATEGIST
- FOR CONTENT MARKETING

Only include blocks that another Skill actually needs.

Avoid unnecessary handoffs.

---

# WHAT NEVER BELONGS IN A HANDOFF

A handoff should never contain:

- Hidden assumptions
- Unverified facts
- Contradictory decisions
- Skill-specific internal reasoning
- Work for the next Skill to rediscover

If the next Skill must guess,

the handoff is incomplete.

---

# SELF-CHECK

Before handing work to the next Skill ask:

> Does the next Skill have everything needed to continue confidently?

If the answer is no,

the handoff is not complete.
