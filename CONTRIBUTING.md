# Contributing to Agent-A

Thank you for your interest in contributing to Agent-A.

Agent-A is an open framework for Human-Governed AI marketing execution. We welcome contributions that improve the framework while preserving its consistency, clarity, and maintainability.

## Before You Start

Before making changes, please read:

- `README.md`
- `governance/constitution.md`
- `governance/execution.md`
- `docs/philosophy.md`
- `docs/design-principles.md`

These documents define how Agent-A is designed and how contributions should align with the project.

---

# Ways to Contribute

You can contribute by:

- Improving existing Skills
- Proposing new Skills
- Enhancing Orchestrators
- Improving Governance
- Fixing documentation
- Adding examples and templates
- Reporting bugs
- Suggesting new ideas through GitHub Discussions

If you're unsure whether a contribution belongs in Agent-A, start a Discussion before opening a Pull Request.

---

# Design Principles

Every contribution should follow these principles:

- One file, one responsibility
- Human-governed decision making
- Strategy before execution
- Evidence before opinion
- Explicit ownership
- Clear handoffs
- Consistency over complexity

Avoid introducing duplicate responsibilities or overlapping roles.

---

# Pull Requests

Before submitting a Pull Request, please ensure:

- [ ] The change follows the Constitution.
- [ ] The change aligns with the Execution framework.
- [ ] Documentation has been updated where necessary.
- [ ] Existing file structure has been preserved.
- [ ] No duplicate responsibilities have been introduced.
- [ ] Markdown formatting has been reviewed.

Please explain:

- What changed
- Why it changed
- Any impact on existing workflows

---

# Reporting Issues

When reporting a bug, please include:

- Description of the issue
- Expected behavior
- Actual behavior
- Steps to reproduce
- Screenshots (if applicable)

For documentation issues, please mention the file and section.

---

# Proposing New Skills

Before proposing a new Skill, ask:

- Does this solve a distinct marketing responsibility?
- Can an existing Skill already perform this work?
- Does it introduce overlapping ownership?
- Does it fit within the current execution workflow?

Agent-A favors specialization over duplication.

---

If you have questions about the project, open a GitHub Discussion or Issue.
